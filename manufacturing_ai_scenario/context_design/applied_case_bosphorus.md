### HumanMatterの判定基準

```
エージェントがやること:
  ・蓄積コンテキストの走査
  ・unchecked/conditions/limitationsの全数抽出
  ・論理式の突合（矛盾・前提欠落・信頼度不整合）
  ・推論過程の明示
  ・Issue発行
  ・HumanMatter判定

エージェントがやらないこと:
  ・顧客との交渉判断（SALES-001: K社交渉）
  ・営業戦略判断（SALES-003: 弱みをどこまで書くか）
  ・経営判断（DEV-001: 認証戦略）
  ・取引先との関係判断（MFG-001のK社転用は本来Yes）
  ・信頼度の「昇格」判断（◇を□にするのは人間+データ）

境界線:
  「事実を突きつける」はエージェント
  「事実に基づいて何をするか決める」は人間
  「放置されている事実を指摘する」はエージェント（SALES-001）
  「放置を解消するために誰に何を言うか」は人間
```

## コンテキストへの還流

Issue発行後、各部門が対応すると新しい議事録が生まれる。その議事録がまたコンテキストに蓄積される。

```
蓄積コンテキスト
  → エージェント推論
  → Issue発行
  → 人間が判断・行動
  → 新しい議事録
  → コンテキストに蓄積
  → エージェント推論（uncheckedが減り、conditionsが充足される）
  → ...
```

K社交渉が完了すれば MFG-001.conditions[0] が充足される。
トルコの規格が判明すれば DES-003.unchecked[0] が解消される。
多気筒NOxデータが出れば RES-001.limitations[0] が縮小される。

**コンテキストは成長する。** uncheckedが減り、[EST]が[DRV]に、[DRV]が[FACT]に昇格していく。その過程が全部出所付きで記録される。
